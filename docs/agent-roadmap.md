# WoW Agent 实施与验收计划

用户于 2026-10-04 确认架构和逐步验收方式，并授权负责人组织工作树内并行研发、测试、验收及本地合并。当前测试目标为正式服客户端。

当前状态：第 0 步已完成并通过负责人验收，结果与体验入口见 [acceptance/stage-0.md](acceptance/stage-0.md)。下一阶段为第 1 步键鼠执行。

## 系统分工

在线闭环：眼 → 当前状态与工作记忆 → 代码 / Jev / 执行大脑 → 手 → 客户端 → 眼。

离线闭环：原始日志 → 任务与遭遇片段 → 学习大脑复盘 → 游戏事实、怪物统计、经验 → 代码 / prompt 改进 → 评估 → 新版本。

| 模块 | 职责 |
| --- | --- |
| core | 配置、启动、主循环、三层决策路由与计划版本 |
| eye | 截图/CV/Seed 接入、字段时效、状态融合、事件与证据 |
| hand | 动作身份、执行闸、输入调度、键鼠 adapter、取消与效果验证 |
| reflex | 可中断技能、确定事实、候选动作与 Jev 选择 |
| brain/execution | 目标、阶段计划、未知场景与异常恢复 |
| memory | 本次运行的目标、承诺、任务进展和失败历史 |
| knowledge | 游戏与怪物事实、角色知识、统计和带证据的经验 |
| learner | 离线复盘、知识更新、代码和 prompt 改进提案 |
| eval | 固定样例、日志回放、实际场景与版本比较 |

在线编排采用 TypeScript，现有 Python 感知与分析代码逐步接入。新模块按阶段建立，旧像素桥保留独立协议及测试。

## WSL 与 Windows 运行边界

| 环境 | 运行内容 |
| --- | --- |
| WSL | TypeScript 主循环、决策、大脑/Jev 接口、工作记忆、学习任务编排；Python 低频视觉调用、日志分析、知识构建和评估 |
| Windows（WoW 所在侧） | C# 截屏、高频 CV、窗口/焦点检查、键鼠执行、输入所有权和独立释放看门狗 |

高频原始帧在 Windows 本地处理，主要向 WSL 输出 JSON。慢模型需要时才读取 JPEG 图像。路径由适配层显式转换，不把 Linux 路径直接传给 Windows，也不依赖子进程当前目录。

动作持续时间、焦点检查和释放期限都由 Windows 本地执行。WSL 调度器发出的是带身份和有限时长的命令；WSL/调度进程中断后，Windows 侧必须能自行停止并释放。第 1 阶段覆盖 EOF、心跳中断、执行器强杀和 Windows 看门狗存活；WSL 重启恢复需要独立真实验收，不能由杀一个 Python/Node 进程的结果代替。

坐标使用客户区物理像素，执行时重新获取窗口位置并转换；覆盖当前高 DPI、移动和缩放窗口等条件。Windows QPC 与 WSL 协调器时钟先标域，后续对时记录误差范围。

## 里程碑

### 第 0 步：工程基线和协议

交付：agent 包、doctor、协议验证入口、纯模拟演示；统一 Observation、ActionIntent、ExecutionReceipt；项目协作规则。

验收：既有 Python/Lua/Windows 离线测试复跑，Windows 程序编译；新包类型检查、协议正反例、CLI 诊断及模拟演示；从 WSL Node 进程实际调用 Windows 窗口枚举与 DPI 探针。doctor 必须区分软件就绪、窗口未绑定、能力未实现和探针失败；不读取凭据、不截真实画面、不发输入。

### 第 1 步：手——键鼠执行

交付：常驻 Windows 输入执行器、接口、键位配置、取消、急停及独立释放看门狗。

验收：输入记录窗口中按键、组合键、点击、滚轮、拖拽、长按各重复 10 次；失焦、断连、取消、执行器被强杀各重复 3 次，确认本程序持有的键和按钮最终释放。随后验证正式服短移动、跳跃、转镜头及界面开关；分别记录输入发送和游戏效果。

### 第 2 步：眼——状态与日志

交付：截图、CV、Seed 接入、带源时间和可靠程度的统一状态、事件及原始证据。

验收：录制真实操作并离线重放；每个关键字段能追溯到来源，未知和迟到结果处理正确，每个动作有关联的前后观察。

### 第 3 步：代码 play 和肌肉记忆

交付：主循环、调度、执行闸、效果验证；move_for、turn_for、jump、open_panel、close_panel、use_action_slot 等技能。

验收：不接模型，连续完成 5 次“确认场景 → 短移动并停止 → 转向 → 跳跃 → 打开并确认背包 → 关闭并确认”；插入失焦、弹窗或取消，检查中断与恢复。无法稳定观察效果时记为未确认。

### 第 4 步：Jev 小脑

交付：动作候选、紧凑题面、答案解析及完整决策日志。

验收：固定样例和有限真实场景中选择接近、转向、技能或等待；无候选外动作，迟到回答按计划版本处理，实际效果和延迟有记录。

### 第 5 步：执行大脑

交付：目标、分阶段计划、工作记忆、异常升级以及三层控制权协调。

验收：接近指定 NPC 并打开交互界面；覆盖正常完成、目标丢失和人为打断，检查大脑重规划和小脑切换计划。

### 第 6 步：学习和经验

交付：任务/遭遇切分、复盘、游戏事实与怪物统计、带证据的经验更新。

验收：从真实日志产生第一批知识；注明适用条件、来源、样本数和反例，区分事实与推断；证明后续决策实际使用了新知识。

### 第 7 步：代码和 prompt 自我迭代

交付：提案、独立工作树修改、回归测试、版本评估与切换。

验收：针对一个真实问题完成发现、修改、验证和发布；冻结代码/prompt/知识/配置版本，保留旧版，对比实际效果。历史回放用于回归检查，不能单独证明替代动作的游戏收益。

## 阶段交付格式

每阶段在 `docs/acceptance/` 保存：对应提交、运行方法、测试命令和退出码、实测日志或截图、尚未验证的部分。负责人完成代码审查和实际验证后本地合并，并向用户提供体验入口。正在实施的阶段不能标成验收通过。

原始日志只追加；派生统计和检索索引放 data；知识数据和读取代码分别放项目根 knowledge 与 agent/src/knowledge。学习者独立运行，已验证的新版本在任务边界切换。
