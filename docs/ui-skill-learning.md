## A. 操作技能图谱

仅在运行库 `out/runtime/agent.sqlite` 扩展，复用现有单写者与事务；冻结世界包不改。跨语言消息与知识快照有唯一 schema，导出版本为 canonical JSON 的 SHA256。状态与技能按照正式服 build、locale、客户区尺寸档和 UI 缩放隔离，不能跨版本默认复用。

| 表 | 内容 |
| --- | --- |
| ui_state | 状态与适用范围：no_game、bnet_home、bnet_login、wow_login、wow_disconnect_dialog、wow_reconnect_page、queue、char_select、loading、in_world、game_menu、tutorial_talk_jaina；硬停止及证据 |
| ui_signature | 归一化 ROI 模板/锚点、源图 SHA、审核者 seed/claude/user/self、确认数/反例数/阈值；裁图与降采样字节均可复核 |
| ui_element | 状态中的按钮/控件，归一化 bbox、角色与来源；未核实身份的选角按钮不执行。世界 NPC 使用当前帧姓名/姓名板定位方法，不能将参考图坐标固化为反射 |

`reach(target_state)` 在已激活且范围匹配的有向图中搜索，成功序列可导出为宏；宏每步仍需当前状态、硬停止与统一执行闸，不能跳过观察。种子审核是出处，不等于两次成功。

## B. 每一步的分层路由

1. Windows 常驻宿主在同一新 WGC 帧匹配全部已加载签名，只读 ROI；高频目标签名计算 <20ms，按实际 QPC 报分布，未达到不写通过。热路径没有 PNG、OCR、模型调用。每个结果保留知识 SHA、目标身份、源帧与 ROI SHA。
2. 当前状态高置信、范围/签名匹配、唯一 active 技能且无上一失败，直接 reflex。多候选或上一失败交 Jev 选择有限候选。未知或连续失败交 Seed 识别状态、硬停止、元素归一化 bbox、预期转换。
3. Seed 通过项目既有标准库 HTTP transport 读取指定 `~/.config/wow-jev/api.env`，型号 doubao-seed-2-0-mini-260428。截图来源、prompt版本/SHA、模型结果与采纳理由落盘。Seed失败/低置信进入审核队列，写当前帧路径/SHA/候选，不长时间手修识别器。人工/模型结果保留原时间，不能冒充当前 CV。
4. Seed/self 提案可生成候选并自主试验，但不能用来源标签代替客观晋升证据；user拒绝或撤销不得由self/Seed覆盖。模型框必须按明确坐标约定转换并经过当前像素/OCR复核，不能靠标记 `proposal` 代替验证。新帧复核当前状态/按钮；未知模态框、失焦或过期阻止输入。TS 调度复用 L4/L3/Body/统一执行闸、ResidentClient和hand，不能直接调用新输入通道。Jaina交谈保留世界引用→局部实测断言→L4→L3路径，recovery仅到可玩状态。
5. 点击统一 MOVE→至少150ms停顿→DOWN约80ms→UP；duration与实际总预算含停顿，MOVE发出与按钮DOWN及游戏效果分别记录。后验默认 +0.5/+1/+3/+8秒，Windows本地计时以实际UP完成为参考；记录预约与实际采集时刻，PNG低频编码不算热路径。

终期目标是已激活技能在Windows本地完成观察/选择/输入/后验，减少WSL往返。本阶段先实现常驻Windows签名与TS分层闭环，未实现本地自治不能写已完成。

## C. 独立常驻学习者

学习者消费持久 skill_attempt 队列，游标/重复尝试保持幂等。慢路 live confirmed 从已核验前图裁 ROI，形成 candidate；未知后状态只建草案并排队识别，不能自称确定事实。input_sent、超时、模拟或相同前后帧不算 confirmed。

候选须至少两次独立 live 确认，跨至少两个 run，最近十次有效尝试成功率至少80%；学习者独立在原始后图重算通过技术验证的目标签名，expected_effect 必须绑定该签名。执行回执完整且释放、不同前后图与帧时序是必要条件。迟到审核与人工补录不把已失败的尝试改判为可晋升成功。成功不抹除失败历史；超时、取消与真实失败分别统计。active 连续两次真实失败/反例退回 candidate；模拟、只读、重放不用于晋升。

每次有效更新保留不可变技能修订并导出知识SHA，运行时在动作边界加载并记录；attempt 带 run、知识、代码和 prompt 版本。坏队列记录隔离并报告，其余记录继续消费。每个签名须验证所有其它已知状态样本不匹配，硬停依据实际屏幕证据且不受审核过滤。`ui-skill audit` 报告呈现裁剪、叠框、负例、前后图与审核链；Claude/user 按报告 SHA 和条目修订定期抽查、撤销；不要求预审批。客观条件未满足保持候选，不得全局放宽。

报告逐轮总时长、模型/人工审核调用数、reflex/Jev/brain/Seed/review占比、尝试/确认与失败。Windows QPC与协调器单调时间分别计算，不直接相减；input issued与effect confirmed始终两条事件。

## E. 闭环练习验收

`practice enter_world` 从当前状态 reach(in_world)，识别安全菜单回到角色选择，再进入世界。先两轮最小闭环，再五轮实测。第1轮允许慢路；第2–3轮已学状态应0模型、0人工审核，实测耗时收敛为加载加少量秒。输出曲线和各轮原件；若加载、失焦、认证、无法识别或释放阻塞，记录未完成轮数及原因，不用模拟填补。

扩展练习退出游戏→战网启动→选角→进世界；后做教程交谈，复用同一学习/后验机制且必须走世界局部数据与既有L4/L3。不可重复的首个交谈样本只能报告n=1，不能宣称p50分布验收。

## F. 工作方式与安全

独立工作树，每个可运行里程碑更新HANDOFF并提交；Python+TS+typecheck全绿后仅正常推送codex/agent-system。先端到端最小闭环，离线回归只覆盖重要不变量。未知场景单点研究≤5分钟，直接慢路或审核请求。

普通输入每步校验WoW身份/当前客户区/DPI/前台；恢复激活遵循已授权点位/可见性/空闲闸，不绕系统限制。按键有限、可取消、由独立Windows看门狗释放，断连停止续发。计划任务最低权限启动，结束删除并GetTask回查；不得改系统设置或输入凭据。测试、模拟、记录窗口与真实游戏效果分别报告。
