# 持续游戏画面的 Seed / Qwen 识别对照

日期：2026-10-05。用户要求先验证效果和识别准确度，再决定是否优化本地Qwen；任务对话留待后续补录。本轮没有优化引擎、权重、量化或图像预处理，也没有程序游戏输入。

## 结论

当前3090上的Qwen3.5-9B Q4_K_M部署尚未达到Seed-2.0-mini的可用识别水平。基础五字段成功率86.6%，Seed为98.1%；Qwen有6次无目标却报告有目标，Seed没有这类误报。死亡状态的可判定字段成功率38.1%对95.2%。两家识别玩家战斗标记都经常返回unknown，不适合作为可靠战斗执行条件。

这是当前部署链路及固定游戏样例的结果。Qwen网关把2048×1536源图缩到1280×960，Seed内部预处理不同，不能据此评价所有Qwen模型或确定错误只来自模型本身。下一步若继续本地路线，应先区分小字预处理损失与模型能力，速度优化不能消除本轮已确认的语义错误。

## 实际录制与缺口

用户准备好后授权十分钟手动打怪与任务操作，负责人运行只读WinEye。最初未核对每个原生实例最多保存128张的配额，也未及时恢复，造成长时间来源缺口；失败记录保持原样。

- 第一段128图，WSL源采样跨度136.765秒，随后artifact_quota_exceeded退出。
- 第二段恢复后63图，源采样跨度67.231秒，随后window_unavailable退出；重新枚举也未检测到可用WoW窗口。
- 共191张有效源图，两个片段合计约204秒，不能称完整十分钟或无缝连续录制。两段run_end均保留failed；总recording sealed=true、active=false、complete=false。

录制工具现以90秒轮换独立原生实例，保留128张保护上限；正常轮换、timeout、SIGTERM封存与POSIX进程组收尾经模拟反例测试及独立代码复审通过。没有补录真实十分钟，也没有把模拟取消证明外推为Windows/WSL强杀恢复。

## 固定选样与盲审

原始证据：`out/acceptance/vision-evaluation/live-1`。在任何模型调用前固定46图，其中第一段30图、第二段16图；含约一秒间隔的目标清除、死亡、退出战斗窗口，以及专精/天赋遮挡、目标框与mouseover混淆负例。按实际场景划分10个事件组，相邻帧不算独立事件。

两名独立Agent逐图看原JPEG，并裁切单位框核验文字和双剑标记；负责人在推理前复核关键状态，在评分后另行审计错误。**不是用户逐图确认的人类金标准**；源图、冻结标签、后续审计分别保留，不因模型表现修改答案。

全图为state五字段；另有combat四字段，3个无前景任务面板的quest负例，共95个图/任务。只读对应单位框中的可见名字、等级、当前目标；截断或遮挡导致不能确认的名字为unknown。combat只按明确双剑/无双剑、死亡字样或明确非零生命状态标注，临界血条未知；数字血量没有显示，不能评估其识别准确度。任务文字与实际接/交任务尚未采集。

固定prompt分三种小JSON任务，在同图上分别请求。两家各95次，串行交替先后、temperature=0.1、关闭思考、max_tokens=256、无历史、不重试。**这是连续素材的独立单帧识别，未测带历史/多帧视频理解。** 源时间仍用录制段内WSL采样时间，不把离线完成时间伪装为源观察时间。

逐图核对recording绑定、原生窗口/PID、run配置、native sample、sample_boundary、artifact路径和SHA后，才读取凭据及调用API。源图上送Seed处于用户已授权的WoW截图范围；不发送其它应用/桌面。原始输出、usage、模型/代码/prompt/来源指纹全部保留，不保存Authorization或请求base64。

## 结果

“成功识别率”按可判定的盲审值计算；模型unknown、格式失败均不算正确。盲审无法判断的字段不进准确率，另记模型是否在这些字段上给出已知答案。明确无目标的target.name=null按有依据的缺席评分，与无法确定的null区分。

| 可判定字段 | 本地Qwen | Seed mini |
| --- | --- | --- |
| 基础五字段 | 187/216，86.6% | 212/216，98.1% |
| 当前目标存在 | 39/46，84.8% | 45/46，97.8% |
| 目标名/明确缺席 | 20/36，55.6% | 36/36，100% |
| 玩家战斗状态 | 13/46，28.3%；33个unknown | 16/46，34.8%；30个unknown |
| 目标死亡状态 | 8/21，38.1%；13个unknown | 20/21，95.2%；1个unknown |
| JSON有效输出 | 95/95 | 95/95 |
| 无目标却报告有目标 | 6次 | 0次 |

全部可判定值（含三个任务负例）为298个：Qwen223正确/29已知错误/46unknown，Seed263正确/4已知错误/31unknown。按事件组宏平均成功率76.2%对86.9%。没有把只统计非空答案的条件准确率当作完整可用率。

本轮端到端中位延迟为Qwen1.635秒、Seed1.341秒，输出任务不同于之前静态三图的短JSON重复实验，不把两轮数据直接混为同一次速度测试。

关键错误已核验：Qwen把头像附近伤害飘字25/19当作等级，把“格挡”当玩家名；将咸水掠蜓/咸水蝾螈读成其它字或其它动物名；在无目标框时从场景/鼠标对象给出当前目标。Seed在专精选择界面漏看被遮挡的目标并误报背包，在拾取窗口上另有背包误报。NPC目标“探险担保人”与鼠标提示的幼龙则两家均正确区分，不列为错误。

独立标签冻结后的段1审计在`score-1/audit-segment01.json`，全部25个Qwen/3个Seed已知错误有源图支持，未修改原标签；段2的4个Qwen目标存在/缺席错误由负责人另看源图复核。双方部分health_text回答“100%”没有直接显示数字支持，不能当作正确识别；当前人工unknown字段不入准确率，因此另保留这类无依据补值的风险，不能由本表推为血量能力通过。

推理前记录的初步门槛为：基础字段至少95%、与Seed差距不超过3个百分点、格式有效率至少98%、关键误报不多于Seed。当前Qwen没有通过效果门槛；门槛是本轮工程判断，不是统计等效证明。

## 复用与验证

`corpus-1/manifest.json`、`annotations-frozen.json`、`criteria.json`在推理前保存；`model-run-1`包含190次原始输出，`score-1`包含逐字段差异与汇总。`corpus-1/executed-vision-evaluate.py`与实测summary代码SHA一致。源JPEG留原录制路径；不复制图片后丢弃来源关联。
